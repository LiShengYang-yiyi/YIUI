# ET9 + YIUI 状态同步：登录、进入地图与移动完整流程

> 本文针对当前仓库的实际代码（Unity 6000.0.25f1、ET9、StateSync、YIUI）编写。
> 文中“当前实现”指 `Packages/cn.etetet.yiuistatesync` 中未被注释的 YIUI Demo 代码；
> `Packages/cn.etetet.statesync/Scripts/HotfixView/Client` 下同名旧 UGUI 示例目前被 `/* ... */` 注释，不应作为运行入口。

## 1. 先给结论

当前工程已经具备一条完整的 Demo 链路：

```text
Init.unity
  -> ET.Init.StartAsync
  -> CodeLoader 加载 Model/ModelView/Hotfix/HotfixView
  -> ET.Entry.Start
  -> Main Fiber 发布 EntryEvent1/2/3
  -> YIUI 初始化并打开 LoginPanel
  -> Router HTTP 获取 Realm/Gate 地址
  -> Realm 校验账号并分配 Gate 登录 Key
  -> Gate 建立 Player 与 Session
  -> LobbyPanel 点击进入地图
  -> GateMap 临时场景创建 Unit
  -> Unit Transfer 到 Map1
  -> 客户端加载 Map1，创建自己的 Unit 和 Skeleton
  -> 鼠标右键点击地图
  -> Gate 转发 C2M_PathfindingResult 到 Map
  -> Map Recast 寻路并广播 M2C_PathfindingResult
  -> Server MoveComponent 计算权威位置
  -> M2C_Stop 对齐最终位置/旋转
 ```

核心原则是：

1. **登录不是一个 RPC**。它包含 Main Fiber、NetClient Fiber、Router HTTP、Realm Session、Gate Session 五个层次。
2. **客户端不决定最终位置**。客户端只发送目标点，Map 服务端寻路、移动、广播结果。
3. **场景资源切换和网络场景切换是两件事**。`M2C_StartSceneChange` 触发客户端加载 Unity 场景，`M2C_CreateMyUnit` 再提供实体初始状态。
4. **Unit 是跨 Map 转移的主体**。转移时通过 BSON 序列化、Location 锁和 ActorId 完成实体迁移。

## 2. 工程和运行前提

### 2.1 版本与启动场景

- Unity 版本：`ProjectSettings/ProjectVersion.txt` 中为 `6000.0.25f1`。
- Build Settings 只有：`Packages/cn.etetet.loader/Scenes/Init.unity`。
- 启动脚本：`Packages/cn.etetet.loader/Scripts/Loader/Client/Init.cs`。
- 资源运行模式由 YooAsset/Resources 配置决定。编辑器调试必须确保 `DefaultPackage` 能加载 `Skeleton` 和 `Map1/Map2`。

### 2.2 GlobalConfig

文件：`Packages/cn.etetet.loader/Resources/GlobalConfig.asset`

当前关键值：

```yaml
CodeMode: ClientServer   # 枚举值 3
SceneName: StateSync
Address: 127.0.0.1:10101
```

`Address` 是 Router HTTP 地址，不是直接的 Realm/Gate UDP 地址。客户端先访问：

```text
http://127.0.0.1:10101/get_router?v=<random>
```

服务器端配置由 StartConfig Excel 导出。`C2G_EnterMapHandler` 固定查找当前 Zone 下名为 `Map1` 的场景；地图传送处理器在 `Map1` 与 `Map2` 之间切换。

### 2.3 ClientServer 和独立服务器

学习和调试可以使用 `ClientServer`，由 Unity 同时启动客户端和服务端 Fiber。独立服务器时：

1. 先将 GlobalConfig 的 `CodeMode` 改为 `ClientServer` 完成初始化和编译。
2. 服务端单独启动后，将客户端 CodeMode 改为 `Client`。
3. 服务器进程需要能读取 `Bin/ET.App.dll` 和对应 `StartConfig`。
4. 客户端的 `Address` 必须指向可访问的 Router HTTP 地址。

项目原有运行说明还要求 Unity、Rider/.NET 8、包注册表和 HybridCLR 环境正确安装，详细基础步骤参见 `Book/1.1运行指南.md`。

### 2.4 从零跑通一次的实际操作

1. 用 Unity Hub 以 Unity `6000.0.25f1` 打开仓库根目录。
2. 等待 Package Manager、脚本导入和资源导入全部结束，不要在编译中途进入 Play。
3. 第一次初始化时执行 Unity 菜单 `ET -> StateSync -> Init`。如果项目已经有 `INITED` 宏，不要反复初始化。
4. 打开 `Packages/cn.etetet.loader/Resources/GlobalConfig.asset`，确认 `CodeMode=ClientServer`、`SceneName=StateSync`、`Address=127.0.0.1:10101`。
5. 当前仓库已经切换到 YIUI Demo。只有确实要重新切换时才打开 `ET -> YIUI Demo` 并选择 YIUI；该工具会修改注释、程序集引用、资源收集和 Init 场景。
6. 打开 C# 工程并完整编译 `ET.sln`。也可按项目约定用 `F6` 编译，确认 `Packages/cn.etetet.loader/Bundles/Code` 下四个热更 DLL 已更新。
7. 打开 `Packages/cn.etetet.loader/Scenes/Init.unity` 并进入 Play。
8. LoginPanel 出现后输入任意非空测试账号和密码。当前 Demo 没有真实账号库，但同一 Gate 上重复登录同一账号尚未实现，第二个客户端请使用不同账号。
9. 登录成功后 LoginPanel 关闭、LobbyPanel 打开；点击“进入地图”。
10. 等待 Map1 加载和 Skeleton 出现。不要在场景加载完成前连续点击按钮。
11. 在地图地面上点击鼠标右键。地面必须带 Collider 且 Layer 为 `Map`，角色才会寻路移动。
12. 按 `T` 在 Map1/Map2 间切换；按 `R` 是热重载。`Q`、`W`、`A` 是协程锁/取消测试键，不是正式玩法输入。
13. 停止 Play 后查看 `Logs` 和 Unity Console。连接失败优先检查 Router HTTP、StartConfig、端口占用、DLL 是否最新，而不是先改移动代码。

使用独立服务器时，将第 4 步改为客户端 `CodeMode=Client`，先通过 `ET -> Server Tools -> Start Server(Single Process)` 启动服务端，再进入客户端 Play。服务端工作目录必须是仓库根目录，不能是 `Bin`。

## 3. 启动与 Fiber 创建

### 3.1 Unity MonoBehaviour 入口

`Init.Start()` 调用 `StartAsync()`，主要动作如下：

```csharp
DontDestroyOnLoad(gameObject);
World.Instance.AddSingleton<TimeInfo>();
World.Instance.AddSingleton<FiberManager>();
await World.Instance.AddSingleton<ResourcesComponent>()
    .CreatePackageAsync("DefaultPackage", true);
World.Instance.AddSingleton<CodeLoader>().Start().NoContext();
```

每帧由 `Init.Update()` 调用 `TimeInfo.Update()` 和 `FiberManager.Update()`，`LateUpdate()` 调用 `FiberManager.LateUpdate()`。ET 的定时器、EntitySystem Update、移动插值都依赖这条循环。

### 3.2 热更程序集和 Entry

`CodeLoader.Start()` 在编辑器中从 `Packages/cn.etetet.loader/Bundles/Code` 读取四个程序集，随后执行：

```csharp
IStaticMethod start = new StaticMethod(modelAssembly, "ET.Entry", "Start");
start.Run();
```

`ET.Entry.Start()` 初始化 Mongo/MemoryPack/Entity 序列化注册和 `SceneTypeSingleton`，然后创建 `SceneType.Main` 的 Main Fiber。

Main Fiber 的 `FiberInit_Main`：

```csharp
root.SceneType = SceneTypeSingleton.Instance
    .GetSceneType(Options.Instance.SceneName);

await EventSystem.Instance.PublishAsync(root, new EntryEvent1());
await EventSystem.Instance.PublishAsync(root, new EntryEvent2());
await EventSystem.Instance.PublishAsync(root, new EntryEvent3());
```

### 3.3 三类初始化事件

- `EntryEvent1_InitShare`：Timer、CoroutineLock、ObjectWait、MailBox、ProcessInnerSender、数学结构序列化注册。
- `EntryEvent2_InitServer`：服务端创建 NetInner，并依据 StartConfig 创建 Realm、Gate、Map 等 Fiber。
- `EntryEvent3_InitClient`（YIUI 版本）：添加 `GlobalComponent`、`ResourcesLoaderComponent`、`PlayerComponent`、`CurrentScenesComponent`，初始化 `YIUIMgrComponent`，最后发布 `AppStartInitFinish`。

YIUI 版本的有效文件是：

```text

Packages/cn.etetet.yiuistatesync/Scripts/HotfixView/Client/UI/UILogin/AppStartInitFinish_CreateLoginUI.cs
```

## 4. 登录完整时序

### 4.1 UI 到 LoginHelper

`AppStartInitFinish_CreateLoginUI` 打开 `LoginPanelComponent`。生成的 Panel 包含两个 `InputField`：`u_ComAccount`、`u_ComPassword`，以及 `u_EventLogin`。

点击事件最终进入：

```csharp
[YIUIInvoke(LoginPanelComponent.OnEventLoginInvoke)]
private static async ETTask OnEventLoginInvoke(this LoginPanelComponent self)
{
    GlobalComponent global = self.Root().GetComponent<GlobalComponent>();
    await LoginHelper.Login(
        self.Root(),
        global.GlobalConfig.Address,
        self.u_ComAccount.text,
        self.u_ComPassword.text);
}
```

`LoginHelper.Login` 会先删除旧的 `ClientSenderComponent`，再新建一个，避免重复登录遗留旧 Fiber：

```csharp
root.RemoveComponent<ClientSenderComponent>();
ClientSenderComponent sender = root.AddComponent<ClientSenderComponent>();
long playerId = await sender.LoginAsync(address, account, password);
root.GetComponent<PlayerComponent>().MyId = playerId;
await EventSystem.Instance.PublishAsync(root, new LoginFinish());
```

YIUI 收到 `LoginFinish` 后关闭 LoginPanel 并打开 LobbyPanel：

```text
LoginFinish_RemoveLoginUI
LoginFinish_CreateLobbyUI
```

### 4.2 ClientSender Fiber

`ClientSenderComponentSystem.LoginAsync` 创建一个独立的 NetClient Fiber：

```csharp
self.fiberId = await FiberManager.Instance.Create(
    SchedulerType.ThreadPool, 0, SceneType.NetClient, "");
self.netClientActorId = new ActorId(self.Fiber().Process, self.fiberId);

Main2NetClient_Login request = Main2NetClient_Login.Create();
request.OwnerFiberId = self.Fiber().Id;
request.Account = account;
request.Password = password;
request.Address = address;

NetClient2Main_Login response = await root.GetComponent<ProcessInnerSender>()
    .Call(self.netClientActorId, request) as NetClient2Main_Login;
return response.PlayerId;
```

NetClient Fiber 的 `FiberInit_NetClient` 添加 MailBox、Timer、CoroutineLock、ProcessInnerSender 和 FiberParentComponent。所有真实网络读写都发生在这个 Fiber，主 Fiber 通过 Actor 消息与它通信。

### 4.3 Router、Realm、Gate

`Main2NetClient_LoginHandler` 的真实顺序如下：

1. 根据 `Address` 创建 `RouterAddressComponent`。
2. 通过 HTTP `get_router` 获取 `Routers` 和 `Realms` 列表。
3. 根据账号哈希选择 Realm：`account.Mode(self.Info.Realms.Count)`。
4. 创建 UDP/WebSocket Router Session，发送 `C2R_Login`。
5. Realm 的 `C2R_LoginHandler` 固定使用 Zone 3，并根据账号哈希选择 Gate。
6. Realm 向 Gate 发送 `R2G_GetLoginKey`，Gate 生成随机 Key 保存 `account -> key`。
7. Realm 返回 Gate 地址、Key、GateId，并延迟 1 秒关闭 Realm Session。
8. 客户端使用返回地址创建 Gate Session，发送 `C2G_LoginGate`。
9. Gate 验证 Key，创建 `Player`、`PlayerSessionComponent`、Location 注册和 Gate MailBox。
10. Gate 返回 `PlayerId`，客户端保存到根场景 `PlayerComponent.MyId`。

协议对应关系：

| 阶段 | 请求 | 响应 | 代码位置 |
|---|---|---|---|
| Main -> NetClient Fiber | `Main2NetClient_Login` | `NetClient2Main_Login` | `cn.etetet.login/Proto/LoginOuter_C_1000.proto` |
| Client -> Realm | `C2R_Login` | `R2C_Login` | 同上 |
| Realm -> Gate | `R2G_GetLoginKey` | `G2R_GetLoginKey` | `LoginInner_S_20001.proto` |
| Client -> Gate | `C2G_LoginGate` | `G2C_LoginGate` | `LoginOuter_C_1000.proto` |
| Client -> Gate 保活 | `C2G_Ping` | `G2C_Ping` | 同上 |

网络读消息由 `NetComponentOnReadInvoker_NetClient` 分类：

- `IResponse`：完成当前 Session RPC。
- `ISessionMessage`：交给 `MessageSessionDispatcher`。
- `IMessage`：通过 `FiberParentComponent.ParentFiberId` 转发到 Main Fiber。

### 4.4 登录完成后的保活和销毁

Gate Session 会添加 `ClientSessionErrorComponent` 和 `PingComponent`。Ping 每 2 秒执行一次，计算 RTT 和客户端/服务器时间差。ClientSender 被销毁时会异步移除 NetClient Fiber，避免网络线程泄漏。

## 5. 进入地图完整时序

### 5.1 LobbyPanel 入口

YIUI Lobby 的按钮事件调用：

```csharp
[YIUIInvoke(LobbyPanelComponent.OnEventEnterMapInvoke)]
private static async ETTask OnEventEnterMapInvoke(this LobbyPanelComponent self)
{
    self.UIBase.SetActive(false);
    await EnterMapHelper.EnterMapAsync(self.Root());
    await self.UIPanel.CloseAsync();
}
```

`EnterMapHelper.EnterMapAsync` 发送 Session RPC：

```csharp
await root.GetComponent<ClientSenderComponent>()
    .Call(C2G_EnterMap.Create());
await root.GetComponent<ObjectWait>()
    .Wait<Wait_SceneChangeFinish>();
EventSystem.Instance.Publish(root, new EnterMapFinish());
```

### 5.2 GateMap：临时承接和传送

Gate 的 `C2G_EnterMapHandler` 做四件事：

1. 从 Gate Session 取出 `Player`。
2. 在 Player 下创建 `GateMap`，其场景类型是 `SceneType.Map`，带 `UnitComponent`、`AOIManagerComponent`、MailBox。
3. 使用 `UnitFactory.Create(scene, player.Id, UnitType.Player)` 创建 Unit，初始位置为 `(-10, 0, -10)`，速度为 6 米/秒。
4. 读取当前 Zone 下的 `Map1` StartSceneConfig，并在当前 Fiber 帧结束后调用 `TransferHelper.TransferAtFrameFinish`。

这里的 GateMap 不是玩家真正游玩的地图，而是为“登录”和“地图传送”复用同一套 Unit Transfer 流程的中间场景。

### 5.3 Unit Transfer 到 Map1

`TransferHelper.Transfer` 的关键步骤：

```text
等待当前 Fiber 帧结束
  -> 读取 Unit.ActorId
  -> Unit.ToBson()
  -> 序列化实现 ITransfer 的组件
  -> Dispose 旧 Unit
  -> LocationProxy.Lock(LocationType.Unit, unitId, oldActorId)
  -> MessageSender.Call(targetMapActorId, M2M_UnitTransferRequest)
```

目标 Map 的 `M2M_UnitTransferRequestHandler`：

1. 反序列化 Unit 并挂入目标 `UnitComponent`。
2. 反序列化 `ITransfer` 组件。
3. 添加 `MoveComponent`、`PathfindingComponent(scene.Name)` 和有序 MailBox。
4. 将位置重置为 `(-10, 0, -10)`。
5. 发送 `M2C_StartSceneChange`。
6. 发送 `M2C_CreateMyUnit`，内容来自 `UnitHelper.CreateUnitInfo`。
7. 添加 AOIEntity，视野半径当前代码为 `9 * 1000`。
8. 解锁 Location，使 Unit 可以继续接收定位消息。

### 5.4 客户端场景切换和实体创建

客户端收到 `M2C_StartSceneChange` 后调用：

```csharp
currentScene?.Dispose();
Scene current = CurrentSceneFactory.Create(
    message.SceneInstanceId,
    message.SceneName,
    root.GetComponent<CurrentScenesComponent>());
current.AddComponent<UnitComponent>();
EventSystem.Instance.Publish(root, new SceneChangeStart());
await root.GetComponent<ObjectWait>().Wait<Wait_CreateMyUnit>();
UnitFactory.Create(current, createMyUnit.Unit);
EventSystem.Instance.Publish(current, new SceneChangeFinish());
root.GetComponent<ObjectWait>().Notify(new Wait_SceneChangeFinish());
```

`SceneChangeStart_AddComponent` 加载：

```text
Packages/cn.etetet.demores/Scenes/{currentScene.Name}.unity
```

所以 `Map1.unity`、`Map2.unity` 必须存在且被 YooAsset/资源加载器收集。

客户端 `UnitFactory.Create` 会：

- 创建 Unit、设置位置/朝向/数值；
- 添加 `MoveComponent`；
- 若 UnitInfo 带 MoveInfo，恢复移动轨迹；
- 添加 ObjectWait 和巡逻路径组件；
- 发布 `AfterUnitCreate`。

`AfterUnitCreate_CreateUnitView` 加载资源名 `Skeleton`，实例化到 `GlobalComponent.Unit`，绑定 `GameObjectComponent` 和 `AnimatorComponent`。之后 `ChangePosition`、`ChangeRotation` 事件把 Entity 状态同步到 Unity Transform。

## 6. 地图点击移动完整时序

### 6.1 客户端输入

当前 `OperaComponentSystem.Update` 只处理鼠标右键：

```csharp
if (Input.GetMouseButtonDown(1))
{
    Ray ray = Camera.main.ScreenPointToRay(Input.mousePosition);
    if (Physics.Raycast(ray, out RaycastHit hit, 1000, self.mapMask))
    {
        C2M_PathfindingResult message = C2M_PathfindingResult.Create();
        message.Position = hit.point;
        self.Root().GetComponent<ClientSenderComponent>().Send(message);
    }
}
```

`mapMask` 在 Awake 中由 `LayerMask.GetMask("Map")` 获取。因此地图碰撞体必须设置为 `Map` Layer，并且必须有 Collider。

### 6.2 Gate 转发

`C2M_PathfindingResult` 实现 `ILocationMessage`，不是 Session RPC。Gate 收到后：

```text
SessionPlayerComponent.Player.Id
  -> MessageLocationSenderComponent.Get(LocationType.Unit)
  -> Send(unitId, actorLocationMessage)
```

这条消息通过 Location 找到玩家 Unit 所在的 Map Fiber。地图切换期间 Location 锁会短暂阻止旧 Unit 接收消息，解锁后消息继续送达新 Unit。

### 6.3 Map 服务端寻路和广播

`C2M_PathfindingResultHandler` 只把任务交给异步移动协程：

```csharp
unit.FindPathMoveToAsync(message.Position).NoContext();
```

`FindPathMoveToAsync`：

1. 读取 `NumericType.Speed`，速度过小直接发送错误 Stop。
2. 调用 `PathfindingComponent.Find(unit.Position, target, points)`。
3. 路径少于两个点时发送错误 Stop。
4. 构造 `M2C_PathfindingResult`，设置 Unit Id 和路径点。
5. 通过 AOI 广播给能看到该 Unit 的玩家。
6. 使用共享 `MoveComponent.MoveToAsync(points, speed)` 进行服务端权威移动。
7. 正常走完后广播 `M2C_Stop(Error=0)`。

服务端移动使用 Timer 帧回调，按照 `distance / speed * 1000` 计算每段时间，以位置插值和旋转插值更新 Unit。再次发起移动会先停止旧移动；旧协程返回 `false` 时不发送多余 Stop。

### 6.4 客户端表现层移动

客户端收到 `M2C_PathfindingResult` 后：

```csharp
Unit unit = root.CurrentScene().GetComponent<UnitComponent>().Get(message.Id);
float speed = unit.GetComponent<NumericComponent>()
    .GetAsFloat(NumericType.Speed);
await unit.GetComponent<MoveComponent>()
    .MoveToAsync(message.Points, speed);
```

客户端 MoveComponent 使用服务端广播的路径和速度做视觉插值，不直接决定网络状态。收到 `M2C_Stop` 后：

```csharp
moveComponent.Stop(message.Error == 0);
unit.Position = message.Position;
unit.Rotation = message.Rotation;
unit.GetComponent<ObjectWait>()?.Notify(
    new Wait_UnitStop { Error = message.Error });
```

最后的位置和旋转以 `M2C_Stop` 为准，避免浮点误差或帧率差造成漂移。

### 6.5 主动停止和编程式移动

客户端发送 `C2M_Stop`，服务端 `C2M_StopHandler` 调用：

```csharp
unit.Stop(1);
```

服务端停止当前 MoveComponent 并广播错误码为 1 的 `M2C_Stop`。如果业务需要“点击移动并等待结果”，可以使用已有的 `MoveHelper.MoveToAsync(Unit, float3)`；它发送目标后等待 `Wait_UnitStop`，并支持通过 ET CancellationToken 取消。

## 7. 地图传送流程

当前 `OperaComponentSystem` 按下 `T` 会发送 `C2M_TransferMap`。服务端 `C2M_TransferMapHandler` 根据当前场景名在 `Map1`、`Map2` 之间选择目标 StartSceneConfig，然后复用 `TransferHelper.TransferAtFrameFinish`。

因此传送和首次进入地图共用以下协议：

```text
C2M_TransferMap
  -> Unit Transfer
  -> M2C_StartSceneChange
  -> Load Map2/Map1
  -> M2C_CreateMyUnit
  -> SceneChangeFinish
```

新增第三张地图时，至少需要：

1. StartConfig 中新增 Map 场景和 ActorId。
2. `Packages/cn.etetet.demores/Scenes/Map3.unity`。
3. Map3 的 NavMesh/Recast 数据。
4. 传送规则不再使用二选一，而是显式校验目标地图。
5. 资源收集配置包含 Map3 和所需 Prefab。

## 8. 可直接复用的业务代码模板

### 8.1 登录按钮

```csharp
public static async ETTask LoginFromUI(Scene root, string account, string password)
{
    if (string.IsNullOrWhiteSpace(account))
        throw new Exception("账号不能为空");

    GlobalComponent global = root.GetComponent<GlobalComponent>();
    await LoginHelper.Login(
        root,
        global.GlobalConfig.Address,
        account.Trim(),
        password);
}
```

生产环境还应增加按钮防抖、请求中状态、错误码到用户提示的映射，以及账号密码长度/字符集校验。

### 8.2 进入指定地图

```csharp
public static async ETTask EnterMap(Scene root)
{
    ClientSenderComponent sender = root.GetComponent<ClientSenderComponent>();
    if (sender == null)
        throw new InvalidOperationException("尚未登录");

    using C2G_EnterMap request = C2G_EnterMap.Create();
    G2C_EnterMap response = await sender.Call(request) as G2C_EnterMap;
    if (response == null || response.Error != 0)
        throw new RpcException(response?.Error ?? ErrorCode.ERR_RpcFail,
            response?.Message ?? "进入地图失败");

    await root.GetComponent<ObjectWait>()
        .Wait<Wait_SceneChangeFinish>();
}
```

当前 Demo 的 `EnterMapHelper` 已经实现了主流程，但没有检查 `G2C_EnterMap.Error`；正式业务建议按上面的模板补上。

### 8.3 点击目标点移动

```csharp
public static void SendMoveTarget(Scene root, Vector3 worldPoint)
{
    ClientSenderComponent sender = root.GetComponent<ClientSenderComponent>();
    if (sender == null || root.CurrentScene() == null)
        return;

    C2M_PathfindingResult request = C2M_PathfindingResult.Create();
    request.Position = worldPoint;
    sender.Send(request);
}
```

注意这段代码只发送目标点；不要在客户端直接 `transform.position = target` 来伪造移动，否则会与状态同步和其他玩家视野内的 Unit 不一致。

## 9. 当前实现的风险和必须补强项

### 9.1 登录与会话

- `C2R_LoginHandler` 目前没有账号密码校验、封禁校验、创角和区服选择，Demo 直接固定 Zone 3。
- `C2G_LoginGateHandler` 找到已有账号时直接抛出 `not write`，重连/顶号/断线恢复尚未实现。
- Realm 返回的 Gate 地址、Key 仅用于当前登录流程，生产环境必须有过期时间、单次消费和防重放策略。
- 当前登录协议通过 UDP/KCP，账号密码没有在业务层加密；应在网关层使用 TLS、短期票据或安全认证服务。
- `LoginHelper.Login` 没有统一的 finally 清理和错误状态，连续点击登录可能产生竞态。UI 必须禁用按钮直到任务完成。

### 9.2 进入地图

- `EnterMapHelper` 捕获异常后只写日志，UI 不会收到失败状态；应返回错误或发布 `EnterMapFailed`。
- `G2C_EnterMap` 当前只作为“请求已接受”的响应，真正完成依赖 `Wait_SceneChangeFinish`。UI 必须同时处理 RPC 失败和场景等待超时。
- `SceneChangeStart_AddComponent` 使用 `LoadSceneMode.Single`，多块大世界不能直接套用，需要改为 Additive/分块加载和卸载策略。
- `M2M_UnitTransferRequestHandler` 将位置重设为固定出生点，正式项目应从角色存档、出生点配置或传送点读取。

### 9.3 移动与寻路

- 客户端目标点必须经过服务端地图边界、NavMesh 可达性、最大距离和移动频率检查，不能信任任意坐标。
- 服务端移动协程仍然依赖 Timer 和单 Fiber 执行；高并发地图应检查每帧移动实体数和消息广播量。
- 当前 AOI 数值存在两处来源：`NumericType.AOI` 设置为 15000，`AOIEntity` 创建半径为 9000。应统一单位和配置来源。
- `M2C_PathfindingResult` 广播给 AOI 玩家，`M2C_Stop` 也广播给 AOI 玩家；玩家离开视野后依赖 `M2C_RemoveUnits` 清理客户端实体。
- 场景中的碰撞体必须在 `Map` Layer，否则右键点击不会发送移动消息。

### 9.4 资源与编译

- `Skeleton` 是通过资源名加载，不是直接引用 Prefab；资源收集、YooAsset 包名和编辑器模拟模式必须一致。
- YIUI Demo 的 `YIUIDemoWindow` 会在 YIUI/旧 ET Demo 间切换注释文件、Init 场景和程序集引用。切换后必须重新生成引用并编译 `ET.sln`。
- 不要同时启用旧 UGUI 事件和 YIUI 同名事件，否则会重复打开面板或产生重复类型/程序集问题。

## 10. 调试顺序和验收清单

按下面顺序排查，能最快定位断点：

1. Unity 是否进入 `Packages/cn.etetet.loader/Scenes/Init.unity`，Console 是否出现 `CodeLoader` 和 `Entry` 初始化日志。
2. `GlobalConfig.SceneName` 是否为 `StateSync`，`Address` 是否能访问 `/get_router`。
3. Router 返回的 `Realms`、`Routers` 是否为空；客户端是否能创建 Realm Session。
4. Realm 日志是否出现 `gate address`，Gate 是否收到 `R2G_GetLoginKey`。
5. Gate 是否返回 `G2C_LoginGate`，客户端 `PlayerComponent.MyId` 是否非零。
6. YIUI 是否从 LoginPanel 切换到 LobbyPanel。
7. 点击进入地图后，服务端是否依次出现 GateMap 创建、Transfer、Map Unit 创建。
8. 客户端是否收到 `M2C_StartSceneChange`、加载 Map1、收到 `M2C_CreateMyUnit`。
9. `AfterUnitCreate` 是否成功加载 `Skeleton`，Unit 是否出现在 `GlobalComponent.Unit` 下。
10. 右键点击时 Raycast 是否命中 `Map` Layer；服务端是否收到 `C2M_PathfindingResult`。
11. `PathfindingComponent.Find` 是否得到至少两个点；客户端是否收到 `M2C_PathfindingResult` 和 `M2C_Stop`。
12. 按 `T` 是否能在 Map1/Map2 间传送，并在切场景期间暂时停止旧地图输入。

建议给每个阶段增加结构化日志字段：`account`、`playerId`、`unitId`、`sceneName`、`sceneInstanceId`、`actorId`、`rpcId`。只打印字符串很难还原跨 Fiber 时序。

## 11. 新业务功能的推荐扩展顺序

1. 先保留现有 `LoginHelper`、`EnterMapHelper`、`MoveHelper`，只替换 UI 和地图资源。
2. 为登录、进入地图、场景加载、移动停止分别定义成功/失败事件和超时。
3. 将账号认证、角色存档、出生点和地图白名单放到服务端，不在客户端写死。
4. 为 `C2M_PathfindingResult` 增加频率、距离、可达性和速度校验。
5. 把 `Map1/Map2` 的硬编码改成 `MapId -> StartSceneConfig` 配置。
6. 最后再做大世界分块、预测/回滚、断线重连和跨服转移，避免在基础链路未稳定时同时改变网络协议和场景管理。
